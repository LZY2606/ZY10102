# 隔离 PKI 签发排练台

这是一个从零实现、只依赖 Go 标准库的本地 PKI 排练系统。系统用事件日志记录根 CA、中间证书模板、主体请求、策略变更、签发、拒绝、吊销和被中断写入的恢复决定；私钥只写入本地 `data/keys/`，数据库和导出包中的 `key_ref` 始终为空，只持久化公开证书字节。

## 启动

```bash
go mod download
go test ./... -count=1
go run ./cmd/server --listen 127.0.0.1:5224
```

然后打开：

```text
http://127.0.0.1:5224
```

默认数据目录是 `./data`，网页在 `./web`。也可以指定：

```bash
go run ./cmd/server --listen 127.0.0.1:5224 --data ./data --web ./web
```

## 操作流程

1. 在“登记根 CA”中创建根证书。根证书作为一个 `root.enrolled` 事件原子持久化，事件中同时包含公开 DER、序列号和状态。
2. 在“登记中间证书模板”中保存中间 CA 主体、公钥、名称约束和 `pathLen`。对应私钥只出现在本地 `data/keys/intermediate-*.pem`。
3. 提交最终实体或中间 CA 请求。候选生成前固定检查：
   - DNS、IP、Email、URI 名称约束；
   - 父证书剩余 `pathLen`；
   - CA/最终实体 key usage；
   - `notBefore/notAfter` 是否在父证书有效期内；
   - 序列号是否唯一；
   - 密钥类型和签名算法是否属于当前策略；
   - 叶子 SAN、通配符和关键扩展策略。
4. 页面列出校验步骤和“请求基线 vs 候选证书”的扩展差异，包含 OID、critical 标志和十六进制 DER。
5. 对候选选择“签发”或“拒绝”；已接受的测试证书可以吊销。
6. 在链验证区显式选择验证时间。时间规则固定为闭区间：`verifyAt == notBefore` 和 `verifyAt == notAfter` 都有效；早于 `notBefore` 或晚于 `notAfter` 无效。
7. 同一主体请求可选择多个签发者，或使用同一中间模板向多个根交叉签发。验证会列出所有合格链，默认链按完整路径指纹拼接后 SHA-256 的字典序稳定选择。

## 幂等性与策略版本

- 候选请求携带幂等键；相同请求体和相同策略版本重复提交时，只返回第一次确定的候选。
- 相同键但请求体或策略版本不同，会返回 `409 Conflict`，不能覆盖第一次结果。
- 策略更新产生新的 `policy.updated` 事件和新版本。已经提交的候选继续绑定旧策略快照；新请求必须使用新的幂等键。
- 序列号在候选事件中占用。即使候选被拒绝，序列号也不会复用。

## 持久化与原子可见性

事件文件位于：

```text
data/events/000000000001.json
data/events/000000000002.json
...
data/state.snapshot.json
```

每个事件包含递增序号、前驱引用、规范化 JSON 载荷的 SHA-256 和总哈希。快照只服务读取：启动时如果快照缺失或落后，会从事件日志重放。签发、拒绝和吊销在写事件前先持久化意图文件，例如：

```text
data/events/intent-<request-id>.intent.json
data/events/intent-revoke-<cert-id>.intent.json
```

证书 DER、状态、事件日志以及序列号占用在同一个候选/签发事件载荷中提交，不依赖跨多个数据库表的第二阶段提交。事件文件通过同目录临时文件 + `rename` 原子替换；事件未出现时，旧快照仍可读取，系统不会显示半成品为已签发。

## 从一次被中断的写入恢复

1. 重启服务。
2. 首页顶部出现“恢复中”横幅，第五个状态列列出残留意图。
3. 对每个意图选择：
   - **完成已提交写入**：当事件其实已经落盘，只是进程在清理意图或刷新快照前退出时使用；系统会确认已有事件并移除意图。
   - **放弃半成品**：当事件尚未落盘时使用；系统写入 `intent.aborted` 审计事件并保留旧状态。
4. 恢复期间，未决请求不会出现在“已接受”；只有明确完成后才改变状态。
5. 若事件日志本身被截断、重排、重复或哈希不匹配，服务启动会返回 `event log corrupt`，应从已验证导出包恢复到空目录，而不是手工改事件。

## 导出和重新导入

通过页面“导出公开包”或：

```bash
curl -o localpki-export.zip http://127.0.0.1:5224/api/export
```

ZIP 中只包含：

- `manifest.json`；
- `policy-snapshot.json`；
- `events/*.json` 事件证明；
- `certificates/*.der` 公开证书；
- `proof.json` 哈希链根。

不包含 `data/keys`、PEM 或任何私钥字节。导入只允许进入空库，并检测：

- ZIP 截断；
- 事件序号缺失或重排；
- 事件 ID 重复；
- 单事件哈希不匹配；
- 前驱哈希不匹配；
- 序列号重复占用；
- 路径穿越成员；
- 非空目标导入。

测试覆盖端到端 HTTP、策略冲突、幂等重复、名称约束失败、pathLen、边界时间、交叉签发多链、吊销链、私钥不导出、提交前失败无半成品、提交后失败仍耐久，以及导入截断/重排/重复检测。
